# STRESS-TEST - D3 -> D4

The D3 object confronted with simulated D4 realities, before real consumption
does it. Domain-agnostic. Software instance: skill `stress-gate`.

```yaml
inputs:   [D3 object, its D2 contract, models of the D4 realities it will meet]
output:   one report. each finding routed by D3 error_classification
          (formal -> fix in place, logic -> D2, systemic -> D1)
grain:    G5 -> G6. a verdict without a run stays G5 and says so
axiom:    the author's checks share the author's blind spots. the gate exists
          to find what they cannot
```

```yaml
steps:
  1 repeat:       same check N times, same conditions. any divergence = the
                  object or the check is unstable. stop
  2 volume:       many random scenarios, invariants checked after EACH one.
                  assert every outcome was reached at least once: a branch
                  never hit proves nothing
  3 differential: an independent oracle, built differently on purpose, judges
                  the same scenarios. compare verdicts, not wording. either
                  side can be wrong: decide per case
  4 mutation:     break one rule of the object at a time. each break must be
                  caught by >= 1 check. caught by nothing -> add the check
  5 endurance:    real object, real load, real duration. measure the drift
                  (latency, wear, memory, fatigue), not only pass or fail
  6 composition:  stimuli combined, overlapped, split, interrupted. one at a
                  time never exercises this
  7 report:       table step -> verdict -> evidence (run or read) -> not run
```

| Step | Software | Physical object | Organisation, process | Document |
|---|---|---|---|---|
| repeat | suite 20x | same test bench 20x | same scenario, several teams | same reading, several readers |
| volume | random actions | randomised loads | case batches | adversarial questions |
| differential | oracle in another language | second method of measure | outside auditor | second independent author |
| mutation | broken rule in code | known defect inserted | removed safeguard | removed clause |
| endurance | soak, RSS, p99 | fatigue cycles | sustained peak period | long-term use |
| composition | pipelined requests | combined loads | concurrent incidents | cross-referenced clauses |

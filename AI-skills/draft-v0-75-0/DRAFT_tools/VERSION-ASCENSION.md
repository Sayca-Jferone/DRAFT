# VERSION ASCENSION - D4 -> next Version or fork (Ascend)

Status: first definition, 2026-11-15. To be confirmed on a real Version.

Turns what consumption reported into D0 material for the next Version, by
measuring the gap between that evidence and FRAME. It is the ascent check of
skill grain (rule 4) run over the whole System: every observed use must serve
a FRAME claim, or it is an orphan.

```yaml
inputs:  [FRAME claims of the closing Version (P1.., S1..),
          D4 FEEDBACKS (G6 evidence, raw G0-G1: perceived purpose, real uses),
          STRESS-TEST reports, optional]
output:  one dated entry in D0 IDEATION.md of the next Version, "ascension
         v<X.Y>". never an edit of D1 or D2: D4 never bypasses them
         (PROPAGATION). or, on a fork, the D0 of a new System
grain:   G6 -> G0
```

```yaml
process:
  1 attach:   each D4 item to the FRAME claim it bears on. none -> orphan
  2 verdict:  per claim, one of
                holds:   evidence confirms it
                drifts:  used, but for something near the claim
                broken:  evidence contradicts it
                silent:  no evidence. not confirmed, not refuted
  3 orphans:  each use no claim covers is a candidate claim. named, never
              silently adopted
  4 emit:     the D0 entry: table claim -> verdict -> evidence, then the
              orphan list. FRAME of the next Version starts from it
guaranty: every D4 item ends attached to a claim or listed as an orphan.
          every claim gets exactly one verdict
```

| Verdict pattern | Means for the next Version |
|---|---|
| all hold | iterate on D1 detail, FRAME stands |
| drifts and orphans | the System is used for something else: re-FRAME first |
| broken on a P claim | the purpose failed: D1 cascade from FRAME |
| mostly silent | D4 collected too little: the next Version owes better tracking |
| orphans form their own purpose | fork: a new System, new Matrix, this D4 as its D0 (SUB-SYSTEMS when it stays a child) |

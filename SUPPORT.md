# Support

> Applies to: `DRAFT Matrix`

This project distinguishes **questions** from **issues**. Putting a question in an issue,
or a formal proposal in a discussion, gets it mis-routed and slows everything down.

## I have a question about how DRAFT works

Use [GitHub Discussions](https://github.com/Sayca-Jferone/DRAFT/discussions) if enabled
on this repository, otherwise open an issue tagged `question`.

Before asking, check:

1. [`README.md`](README.md) - the method itself, especially `[OVERVIEW]` and the
   per-dimension `<details>` sections
2. [`AI-skills/`](AI-skills/) - the operational form used by AI agents
3. Existing issues and discussions - your question may already be answered

## I found a bug, ambiguity, or gap in the method

Open an issue using the matching template:

- **Bug / inconsistency** - the method contradicts itself or an example is broken.
- **Unresolved FMBOA / BIOPGE ambiguity** - an A-XX you could not resolve or `[ASSUMED]`
  while applying DRAFT to a real System.
- **Method amendment proposal** - you believe the Matrix itself should change.
- **Terrain feedback (D4)** - a field report, no proposal attached.

See [`CONTRIBUTING.md`](CONTRIBUTING.md) for what happens next, in particular the
propagation-check workflow before any Pull Request.

## I want tooling or governance changed, not the method

Use the **Feature request** template. This is for repository tooling, templates, or
process - not for D0-D4, FMBOA, BIOPGE, propagation, or hard rules.

## I found a security issue

Do not open a public issue. See [`SECURITY.md`](SECURITY.md).
